# 03 任务拆解与验收

本文把设计切成可独立验收的施工单元。每个任务都有明确的交付物、依赖和**可执行**的验收命令，不接受"看起来能跑"。

复杂度：S（半天内，单一文件级改动）/ M（跨 2–4 个包）/ L（跨模块，需要设计对齐）。
不使用工期估算，只标依赖顺序与并行可能性。

## 里程碑视图

```
M0 地基 ──┬─▶ M1 索引内核 ──┬─▶ M2 移动与版本 ──┬─▶ M3 局域网面 ──┬─▶ M5 加固与验收
          │                 │                   │                 │
          ├─▶ M4a 外部面 ───┘                   └─▶ M3c 控制台 ───┤
          └─▶ M4b 快照 ───────────────────────────────────────────┘
```

- M1 与 M4a 可以并行（都只依赖 M0）
- M2 必须在 M1 之后（依赖事件分类与 object 模型）
- M3 依赖 D-01 已拍板；可以与 M4b 并行
- M3c 控制台依赖 T-34 状态机；前端部分可以在 T-34 之前先用假数据做（见 T-70）
- M5 必须最后做，且必须由非编码者按本文命令逐条执行

**T-21 验收（最关键的一条）**

```
# 1. 记录基线
sqlite3 data\fsgw.db "SELECT COUNT(*) FROM versions;"  → N0
# 2. 清理整理：移动 200 个文件到新目录、重命名 50 个、建 10 个新目录
# 3. 等待 3 秒后复查
sqlite3 data\fsgw.db "SELECT COUNT(*) FROM versions;"  → N1
sqlite3 data\fsgw.db "SELECT COUNT(*) FROM path_history WHERE change=2;"  → 250
# 断言：N1 == N0（移动零版本）；path_history 恰好 250 条 move
# 断言：所有被移动文件 object_id 与移动前一致
sqlite3 data\fsgw.db "SELECT object_id, path FROM files WHERE path_key LIKE '%新目录%' LIMIT 5;"
```

**T-22 验收**

```
# 在 D:\ 建第二个共享根，把文件从 D:\share 移到 D:\share2（同卷不同根）
# 再把 D:\share2 建到另一块物理盘，重复一次
# 断言：同卷根间移动 object_id 不变，move_kind=1
# 断言：跨盘移动若哈希匹配成功 → move_kind=2 且 object_id 不变
# 断言：跨盘且内容已改 → move_kind=3 且存在 move_unconfirmed 标记，不做错误合并
```

**T-26 验收**

```
sqlite3 data\fsgw.db "SELECT status FROM files WHERE path_key='x/y.txt';"  → 3
sqlite3 data\fsgw.db "SELECT state FROM objects WHERE object_id=(...);"      → 2
# 断言：文件已从 ReadDir 结果消失，但 versions 记录仍可查
```

**T-71 验收（安全是主断言，不是附注）**

```
TOKEN=$(cat data\control.token)

# 无 token
curl -i http://127.0.0.1:8444/api/status
# 断言：401，响应体不含任何状态字段

# 错误 token
curl -i -H "X-FSGW-Token: bad" http://127.0.0.1:8444/api/status
# 断言：401

# 正确 token
curl -s -H "X-FSGW-Token: $TOKEN" http://127.0.0.1:8444/api/status
# 断言：200，applied_state 字段存在

# 模拟浏览器里的第三方页面发起请求
curl -i -H "X-FSGW-Token: $TOKEN" -H "Origin: http://evil.example" http://127.0.0.1:8444/api/status
# 断言：403

# 模拟 DNS rebinding：Host 已被换成攻击者域名
curl -i -H "X-FSGW-Token: $TOKEN" -H "Host: evil.example:8444" http://127.0.0.1:8444/api/status
# 断言：403

# 预检请求必须不被放行
curl -i -X OPTIONS -H "Origin: http://evil.example" \
     -H "Access-Control-Request-Method: POST" http://127.0.0.1:8444/api/switch
# 断言：响应里没有 Access-Control-Allow-Origin / -Methods / -Headers

# 绑定地址不可改
# 配置 ui.bind: 0.0.0.0:8444 后启动
# 断言：启动失败并明确指出只允许回环地址
```

## 完成定义（DoD）

一个任务只有同时满足以下五条才算完成：

1. 代码合并，`go build ./...` 与 `go vet ./...` 无输出
2. 该任务的验收命令在干净环境（删掉 `data\` 重来）可重复通过
3. 新增的写路径有对应审计记录
4. 新增的失败分支有日志，且日志里能定位到具体路径
5. 若改动了 `02` 中的表结构或事务顺序，`02` 已同步更新

涉及控制台的额外两条：

6. 前端不得内联任何业务校验逻辑，只做展示与输入收集；删掉前端的 `app.js` 后，所有约束仍由后端独立成立
7. 新增的 API 必须在 `01` 第 11.3 节表格中登记，不接受"临时接口"
