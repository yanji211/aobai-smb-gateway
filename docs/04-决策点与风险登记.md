# 04 决策点与风险登记

评审时逐条过。每条给出备选、代价、推荐，以及"如果不决策会怎样"。

---

## D-01 SMB 实现路线：托管系统共享，还是自研协议栈

### 事实前提

纯 Go 生态里没有可用于生产环境的 SMB2/3 **服务端**实现。开源库绝大多数是客户端。服务端要正确处理 credit 授予、compound request、signing、encryption、lease/oplocks、durable handle、change notify、DFS 引用、IPC 命名管道等子协议，任何一项缺失都会让某类客户端连不上或行为异常。这是方案里唯一一个"看起来是技术选型、实际是可行性问题"的点。

### 备选

| 选项 | 做法 | 得到什么 | 失去什么 |
| --- | --- | --- | --- |
| A（推荐） | 托管 Windows 原生 SMB 共享，网关负责创建、配置、开关、索引 | 电视与手机兼容性最好，零协议开发，稳定性等同系统 | 网关不在写路径上，写前捕获做不了；匿名受系统策略约束 |
| B | 自研 SMB2/3 服务端 | 唯一能同时拿到写前捕获与精细 VFS 控制 | 协议栈体量巨大，兼容性回归风险高，第一版几乎不可能稳定 |
| C | 局域网写面改用 WebDAV | 实现成本最低，能与外部面复用代码 | 破坏"零安装"，安卓电视与手机文件管理器体验极差 |
| D | A + VSS 卷影兜底 | 保留 A 的兼容性，内容级历史由卷影提供 | 时间粒度粗（分钟级），需要卷影权限与额外空间 |

### 推荐

**第一版选 A，并把 `smbhost` 设计成可替换接口**：

```go
type Provider interface {
    EnsureShare(spec ShareSpec) error   // 幂等创建/更新
    RemoveShare(name string) error
    Status(name string) (ShareStatus, error)
}
```

两个实现：`hosted`（A，第一版）、`native`（B，v2 实验分支）。上层与协议无关，切换不动业务代码。

如果后续确认"必须写前捕获"，先评估 D，再评估 B。不要因为"方案里写了网关当 SMB 服务端"就硬上 B。

### 不决策的后果

M3 阶段会卡住，因为 `smbhost` 的接口形状取决于这个选择。

## D-02 内容快照的承诺边界

### 事实前提

用户已确认"整个共享可读写"。但 SMB 走系统共享意味着删除与覆盖都由系统内核完成，网关拿不到任何前置钩子。硬链接保旧 inode 的技巧在就地覆盖场景完全失效（见 `02` 第 6.1 节）。

因此实际能承诺的只有：

- 索引版本链（元数据）：全部来源，可信
- 内容快照：网关自身写路径可信；SMB 来源只能 best-effort
- 删除恢复：只有在快照存在时才能恢复，且 SMB 删除是不可拦截的真删

### 备选

| 选项 | 承诺 | 代价 |
| --- | --- | --- |
| A | 只做 L0 索引版本链 + L1 网关写路径快照，SMB 来源明确标注"无可靠历史" | 最诚实，但用户预期落差大 |
| B（推荐） | A + 可选启用 VSS 定时卷影（默认 15 分钟），对外把卷影时点作为"完整版本"呈现 | 需要额外磁盘空间（增量，通常 5–15%），需要管理员权限，恢复粒度受间隔限制 |
| C | 自研协议栈或 minifilter 实现真写前捕获 | 见 D-01 B，第一版不可行 |

### 推荐

**选 B**，但把 VSS 做成"可选、默认关闭、显式开启时给出空间提示"。UI 三档标记必须清楚：

- `完整`：L1/L3 产出
- `尽力`：L2 产出，可能不完整
- `仅元数据`：只有 L0

### 不决策的后果

`/versions` 页面会出现"用户以为能下载三天前的文档，实际下到半个损坏文件"的情况。这比没有历史版本更糟。

## D-03 匿名 SMB 在 Windows 上的真实可行性

### 事实前提

"局域网零安装"要求匿名访问。但 Windows 10 1903 之后，SMB2/3 的匿名（Guest）访问在**客户端侧**默认被拒绝，需要改注册表：

```
HKLM\SYSTEM\CurrentControlSet\Services\LanmanWorkstation\Parameters
  AllowInsecureGuestAuth = 1 (DWORD)
```

服务端侧还需要：Guest 账户启用、共享授权给 Guest、`NullSessionShares` 包含共享名、`RestrictNullSessAccess` 允许。

另外：

- 安卓电视/小米电视原生播放器：通常支持匿名 SMB2，可用
- iOS「文件」App：**不支持**匿名，必须账号密码
- Windows 资源管理器：默认隐藏匿名共享，需启用"不安全的来宾登录"
- Windows 默认禁止空密码账户远程登录（`LimitBlankPasswordUse=1`），所以账户模式的口令不能为空

### 推荐

配置 `smb.auth: both`：

- 匿名路径服务电视
- 专用低权本地账户 `fsgw`（随机口令，写在 `config.yaml` 与一页说明里）服务手机与 PC

首次连接时提示"iOS 需要账号密码"，不要承诺"所有设备都零配置"。

### 不决策的后果

验收时"手机连不上"会被当成 bug 排查很久，实际是客户端策略。

## D-04 整个共享可读写的删除风险

### 事实前提

用户选择"整个共享可读写"。这意味着任何局域网设备可以删除 `D:\share` 下任何文件，网关无法拦截。

### 可选缓解（不影响已定策略）

1. 默认开启 `deny_delete=false`，但提供 `fsgw restore <path> [--at <time>]` 从快照恢复
2. 可选 `deny_delete=true`：通过共享 ACL 实现只读删除（`Change` 权限去掉 `DELETE`），代价是客户端删除操作报错而非静默
3. 每日一次 `snapshots.pinned` 快照（不受配额清理），成本可控

### 推荐

保留用户选择（可读写可删除），但**默认启用 1 + 3**，把"误删恢复"做成可用功能而不是事后解释。

## D-05 跨卷移动的定性

同卷移动有硬保证（FileID 不变）。跨卷移动只能哈希 + 大小 + 时间窗口匹配，属于尽力而为。

### 推荐

如实按 `02` 第 7 节处理，匹配不上就记"删除 + 新增"并打 `move_unconfirmed`。**不要为了让路径历史看起来漂亮而强行合并**——错并会把两个不相干文件的版本链混在一起，比丢失更危险。

第一版共享根只有 `D:\share` 一个卷，跨卷场景实际不会触发。但要保留代码路径，因为将来加第二个共享根（比如移动硬盘）就会遇到。

## D-06 外部面的暴露方式

### 备选

| 选项 | 做法 | 风险 |
| --- | --- | --- |
| A（推荐） | 只绑 `127.0.0.1`，由隧道（Cloudflare Tunnel / Tailscale / frp）对外 | 最低。证书、DDoS、端口扫描都由隧道侧处理 |
| B | 内置 TLS，直接监听公网端口 | 需要自管证书、自管封禁、自管漏洞响应 |
| C | 只在内网 VPN 内访问 | 最安全，但"在外面也能看"的需求落空 |

### 推荐

**A**。配置默认 `bind: 127.0.0.1:8443`，文档明确不提供一键公网监听。若用户坚持 B，要求先配好证书与 IP 白名单。

## D-07 "无缓存层"的性能风险

讨论稿明确选择"目录列举直查 SQLite，不设内存缓存"。这在 Windows 上有一个具体风险：电视 SMB 客户端列举大目录（数千文件）时会高频重复请求。

### 缓解

- 覆盖索引 + `ORDER BY` 走索引，实测目标为 1 万条目 <50ms
- 协议层允许 500ms 内的同路径重复列举复用结果（短生命周期、无失效问题）
- 若实测不达标，退路是加"目录条目计数 + 版本号"的极简缓存：目录内容变更时版本号 +1，缓存键含版本号，天然无失效问题

### 定性

这是性能风险，不是正确性风险。正确性上无缓存的设计明显更优（移动语义精确、无失效 bug）。**先按无缓存实现，实测不达标再上版本号缓存**，不要提前优化。

## D-08 DLNA 库选型

需要在 T-31 阶段评估。约束：

- 必须支持 Windows 下的 SSDP 多播（多网卡时需指定接口，否则可能只在一个网卡上广播）
- 必须支持自定义 ContentDirectory 后端（从我们自己的索引取数据，而不是扫目录）
- 必须允许只暴露媒体类型

候选方向：`anacrolix/dms` 的分层结构可参考，但其内置文件系统后端需要替换成索引后端。若改造量超过自研 SSDP + SOAP 最小集（只需 Browse + 媒体 URL），则自研更可控。

定性：中等风险，可延后到 M4。

## D-09 权限模型：服务以 LocalSystem 运行

网关需要三样提权能力：增删防火墙规则、创建 SMB 共享（`net share` / `New-SmbShare`）、读卷序列号。

以 LocalSystem 跑服务是最省事的路径，但意味着**网关进程被攻破即等价于系统管理员**。考虑到网关的对外面是只读 WebDAV 与匿名 SMB，这个风险不能忽略。

### 缓解

1. WebDAV 处理器严格白名单，路径校验在 VFS 单点完成，不允许任何字符串拼接后直接 `os.Open`
2. SMB 面不经过网关进程（系统提供），网关进程不解析任何来自 SMB 客户端的字节
3. 只读面与提权能力分离：v2 可考虑拆成两个进程（`fsgw-core` 无提权 + `fsgw-priv` 有提权，通过命名管道通信，接口只暴露"加规则/删规则/建共享/删共享"四个动作）

### 推荐

第一版单进程 LocalSystem，但**把提权操作收敛到 `internal/platform` 的四个函数**，为 v2 拆进程留出切面。

## D-10 控制台形态：HTML 前端 + Go 后端

### 已定

用户明确要求"用户交互控制前端使用 HTML，后端 Go"。本文档据此把原方案的命名管道控制通道替换为回环 HTTP API，CLI 与网页控制台共用同一套接口（见 `01` 第 11 节）。

### 这条约束带来的三个具体决策

| 子决策 | 选择 | 替代方案放弃原因 |
| --- | --- | --- |
| 前端构建方式 | 手写 HTML/CSS/JS，`embed.FS` 打包，无 npm | 引入 Vite/React 会带来 node_modules、构建产物与版本漂移，而控制台只有五个区块 |
| 前后端通信 | REST + SSE | WebSocket 需要额外握手与心跳管理，SSE 单向足够，`EventSource` 浏览器原生支持 |
| 后端框架 | 标准库 `net/http` + Go 1.22 `ServeMux` | chi/gin 提供的中间件能力，这里只需要一个 token 校验和一个日志，不值得引依赖 |

### 必须一起定下的安全边界

控制台一旦能驱动开关，它就成了"能把共享推到公网"的遥控器。而它跑在 `127.0.0.1`，天然会被**用户浏览器里的任意网页**触达。四道防线（token / Origin / Host / 无 CORS）不是可选项，写进 `01` 11.4 之后不得删减。

### 不做的事

- 不做 Electron 或 WebView2 外壳（多一套运行时，收益只是托盘图标）
- 不做移动端适配（控制台只在本机用）
- 不做前端状态管理库（五个区块的局部刷新，`fetch` + 赋值就够）

## 风险登记表

等级：高 = 会导致方案不成立或数据错误；中 = 影响体验或需要改设计；低 = 可控。

| ID | 风险 | 等级 | 概率 | 缓解 | 监控信号 |
| --- | --- | --- | --- | --- | --- |
| R-01 | SMB 自研路线被低估，M3 卡死 | 高 | 中 | D-01 选 A，接口隔离 | 若 M3 前期出现"要不要自己写协议"的讨论，立即回到 D-01 |
| R-02 | 快照承诺与实际能力不符，造成数据丢失预期 | 高 | 高 | D-02 选 B，UI 三档标记 | `/versions` 中 `partial` 占比 |
| R-03 | 关闭网关时误删用户的其它 SMB 共享或 445 放行规则 | 高 | 中 | 只删本网关创建的共享（名字前缀校验）；445 防火墙规则的删除做成显式选项 `exclusive: true` | 关闭后 `net share` 列表比对 |
| R-04 | `ReadDirectoryChangesW` 缓冲溢出导致索引落后 | 中 | 高 | 64 KiB 缓冲 + 溢出即子树重建 + 6h 抽查 | `fsgw_events_overflow_total` |
| R-05 | 大目录 `ReadDir` 延迟超电视客户端超时 | 中 | 中 | D-07 的三级缓解 | p99 列举延迟 |
| R-06 | 匿名 SMB 在某些客户端不可用被当成 bug | 中 | 高 | D-03 `both` 模式 + 一页说明 | 连接失败日志按客户端类型分类 |
| R-07 | SQLite 写队列积压导致移动事件滞后 | 中 | 中 | 结构性优先调度 + 深度告警 | `fsgw_write_queue_depth` |
| R-08 | 长路径 / 特殊字符导致索引与磁盘不一致 | 中 | 中 | `\\?\` 前缀统一、VFS 单点校验、非法字符拒绝 | reconcile 差异计数 |
| R-09 | LocalSystem 权限放大攻击面 | 中 | 低 | D-09 收敛提权函数 | 审计中的异常路径访问 |
| R-10 | 移动配对超时误判，产生假的删除+新增 | 中 | 中 | 500ms 阈值 + 源路径存在性复核 | `move_unconfirmed` 计数 |
| R-11 | 卷影（若启用）占用空间超预期 | 低 | 中 | 配额上限 + 空间告警 | 快照区占用 |
| R-12 | DLNA 多网卡只广播一个接口 | 低 | 中 | 配置显式网卡 | 电视发现失败 |
| R-13 | 网关重启期间 SMB 写入未入索引 | 低 | 中 | 启动时对共享根做一次全量对齐（仅首次或超过 24h 未对齐） | 启动耗时与对齐节点数 |
| R-14 | 浏览器里的第三方页面驱动控制台开 WAN（CSRF / DNS rebinding） | 高 | 中 | `01` 11.4 四道防线；T-71 把伪造 Origin/Host 作为主断言 | 403 计数按原因分类，突增即告警 |
| R-15 | 把校验写在前端，后端被绕过 | 高 | 中 | DoD 第 6 条：删掉 `app.js` 后约束仍须成立 | 代码评审专项检查 |
| R-16 | 前后端字段漂移（改了 API 忘改前端） | 中 | 高 | `01` 11.3 表格作为唯一契约，改接口必须同一提交内改表格与前端 | 契约测试：对每个响应做字段白名单校验 |
| R-17 | `fsgw ui` 把 token 打进 URL，被截图或录屏泄漏 | 中 | 低 | token 走 fragment（不进 Referer、不进服务端日志）；支持 `fsgw ui --rotate` 轮换 | 审计中出现陌生来源的 401 |

## 需要在评审会上拍板的四件事

1. **D-01 选 A**（托管系统共享）—— 决定 M3 的形状
2. **D-02 选 B**（含可选 VSS）—— 决定对用户承诺什么
3. **D-06 选 A**（只绑回环 + 隧道）—— 决定外部面的部署文档怎么写
4. **D-10 的安全边界不删减**（token / Origin / Host / 无 CORS）—— 决定控制台能否安全存在

其余（D-03 到 D-09）按本文推荐值执行即可，不需要单独讨论。
