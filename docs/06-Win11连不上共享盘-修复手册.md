# 06 · Win11 连不上共享盘：修复手册（可交给 agent 执行）

> 目标读者：任何一台 Windows 11 上的 agent 或运维人员。照本手册执行即可完成诊断与修复，不需要先联系服务端维护者。
> 适用服务：`\\192.0.2.11\share`（Debian 上的 fsgw，纯 Go SMB2/3 服务端）。

---

## 0. 30 秒速判

先跑这一段，按结果跳转对应章节，不要一上来就动注册表。

```powershell
"net use"; (cmdkey /list:192.0.2.11); Test-Path 'Z:\'
$r = Test-NetConnection 192.0.2.11 -Port 445 -WarningAction SilentlyContinue; "445=$($r.TcpTestSucceeded)"
try { "UNC=" + ([System.IO.Directory]::GetFileSystemEntries('\\192.0.2.11\share')).Count } catch { "UNC失败: " + $_.Exception.Message }
```

| 现象 | 结论 | 去哪 |
| --- | --- | --- |
| `445=False` | 网络层不通，改注册表也没用 | §6 |
| `445=True` 且 `UNC` 列目录成功，只有 `Z:` 不可用 / 不存在 | **开机映射失联**（最常见） | §4 |
| `UNC` 也失败，报 `0x80004005` / `错误 67` / “策略阻止了未经验证的来宾访问” | 走了来宾身份，被 Win11 24H2+ 的强制签名挡掉 | §3 |
| 能打开、能读，但复制/新建/删除被拒（`目标文件夹访问被拒绝`） | 服务端共享是只读 | §5 |
| 报 `1326` 用户名或口令不正确 | 账号或口令错（口令见 §1） | §2 / §3 |
| 报 `1219` 多重连接冲突 | 同一服务器存在多条不同凭据的连接 | §3 第 5 步 |

## 1. 环境事实（不要猜，照这个对）

| 项 | 值 |
| --- | --- |
| 服务端 | `192.0.2.11`（Debian，hostname `linux-fsgw`） |
| 共享 | `share` → `/srv/share`，**可读写** |
| 端口 | 445（SMB）、8443（WebDAV 网页）、8200（DLNA/电视） |
| SMB 账号 | `admin` / `changeme`（通用，EXE 默认）<br>`fsgw` / `changeme`（老账号）<br>此外还登记了各机器专用账号，见服务端账号表 |
| 网页版 | `http://192.0.2.11:8443/share/`，Basic 认证，**地址必须带 `/share/`** |
| 只读面 | 网页端只允许 GET/HEAD/PROPFIND，上传/删除一律 405，属设计 |

盘符约定 `Z:`；被占用时顺延为 `Y:`，不影响使用。

## 2. 最快路径：跑 EXE

`共享盘一键修复.exe`（2.7 MB，单文件，免安装）→ 双击 → UAC 点“是”。

它会做 9 步：探 445 → 网络位置设为专用 → 修注册表（`AllowInsecureGuestAuth=1`、`LmCompatibilityLevel=3`、必要时放开出站 NTLM）→ 查 `LanmanWorkstation` → 清旧映射与旧凭据 → `cmdkey` 存账号 → 映射盘符 → 列目录 + 写测试文件 → 开资源管理器。

结束会停住显示结果，同目录留 `fsgw-connect.log`。**重复运行无副作用。**

```powershell
.\共享盘一键修复.exe -diag                 # 只体检，不改任何东西
.\共享盘一键修复.exe -drive Z               # 指定盘符
.\共享盘一键修复.exe -ip 192.0.2.11 -share share -user admin -pass changeme
```

EXE 不可用（比如被杀软拦了）时走 §3 手动版，两者等效。

## 3. 手动修复：让机器走「账号」而不是「来宾」

**为什么要这么做**：Linux 侧 `auth: guest` 是“账号 + 来宾并存”。来宾会话没有会话密钥，签不了名，而 Win11 24H2 起客户端强制 SMB 签名，于是直接报“策略阻止了未经验证的来宾访问”。所以正确方向不是放开来宾，而是让每台机器用登记过的账号登录。

按顺序执行（**需要管理员 PowerShell**；第 1、2 步可跳过）：

```powershell
# 1. 网络位置设为专用（让资源管理器能发现设备，不影响 SMB 本身）
Set-NetConnectionProfile -NetworkCategory Private

# 2. 注册表：允许来宾兜底 + 强制 NTLMv2（服务端只存 NT 哈希，必须 NTLMv2）
$lw = 'HKLM:\SYSTEM\CurrentControlSet\Services\LanmanWorkstation\Parameters'
Set-ItemProperty $lw -Name AllowInsecureGuestAuth -Value 1 -Type DWord
Set-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\Lsa' -Name LmCompatibilityLevel -Value 3 -Type DWord

# 3. 确认 SMB 客户端服务在跑
Get-Service LanmanWorkstation | Start-Service -ErrorAction SilentlyContinue

# 4. 清掉指向该服务器的旧映射与旧凭据（1219 冲突的根源）
net use * /delete /y
cmdkey /delete:192.0.2.11

# 5. 存入账号凭据（持久化，重启后仍有效）——关键一步
cmdkey /add:192.0.2.11 /user:admin /pass:changeme

# 6. 映射盘符
net use Z: \\192.0.2.11\share /persistent:yes

# 7. 验收（必须真的能列目录 + 写入）
(Get-ChildItem Z:\).Count
[System.IO.File]::WriteAllText('Z:\_agent_test.txt','ok'); Get-Content 'Z:\_agent_test.txt'; Remove-Item 'Z:\_agent_test.txt'
```

> 如果这台 Windows 的登录用户名恰好也在服务端账号表里、且口令一致，可以省略 `/user:` 直接用当前身份隐式认证。**不要依赖这个巧合**，显式存凭据更稳。

## 4. 开机后 Z: 停在「不可用」：自动重连

### 4.1 症状

刚开机，`net use` 里盘符状态是 `不可用`，`Test-Path Z:\` 为 `False`，但 `\\192.0.2.11\share` 直接访问却正常。

### 4.2 原因

Windows 在登录时恢复持久映射（`HKCU\Network\Z`），那一刻网络或 SMB 会话还没就绪；**失败后它不会重试**，盘符就永久卡在“不可用”。凭据存在也没用，因为会话根本没建立。

### 4.3 立即恢复（一条命令）

```powershell
net use Z: /delete /y; net use Z: \\192.0.2.11\share /persistent:yes
```

### 4.4 装成开机自动重连（强烈建议每台机器都做）

写脚本 `%LOCALAPPDATA%\fsgw-reconnect\reconnect.cmd`（**注释只能用 ASCII**，中文注释会被 cmd 的 GBK 代码页切错，报 `'細Windows' 不是内部或外部命令`）：

```bat
@echo off
setlocal
set UNC=\\192.0.2.11\share
set DRIVE=Z:

dir %DRIVE%\ >nul 2>&1 && exit /b 0

net use %DRIVE% /delete /y >nul 2>&1

for /l %%i in (1,1,12) do (
    net use %DRIVE% %UNC% /persistent:yes >nul 2>&1
    dir %DRIVE%\ >nul 2>&1 && exit /b 0
    ping -n 6 127.0.0.1 >nul
)
exit /b 1
```

注册计划任务（登录后延迟 20 秒；`net use` 不需要管理员，用 Limited 即可）：

```powershell
$act = New-ScheduledTaskAction -Execute 'C:\Windows\System32\cmd.exe' `
       -Argument '/c "%LOCALAPPDATA%\fsgw-reconnect\reconnect.cmd"'
$trg = New-ScheduledTaskTrigger -AtLogOn -User "$env:USERDOMAIN\$env:USERNAME"
$trg.Delay = 'PT20S'
$set = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries `
       -StartWhenAvailable -Hidden -ExecutionTimeLimit (New-TimeSpan -Minutes 5)
Register-ScheduledTask -TaskName '共享盘自动重连' -Action $act -Trigger $trg -Settings $set -Force
```

验证：

```powershell
net use Z: /delete /y                      # 制造故障
& "$env:LOCALAPPDATA\fsgw-reconnect\reconnect.cmd"; "退出码=$LASTEXITCODE"
Test-Path 'Z:\'                            # 应为 True
Start-ScheduledTask -TaskName '共享盘自动重连'
(Get-ScheduledTaskInfo -TaskName '共享盘自动重连').LastTaskResult   # 应为 0
```

期望耗时约 0.2～1 秒；盘符正常时脚本会立刻退出，不动现状。

## 5. 能读不能写

SMB 侧写入由服务端 `shares[0].writable` 决定，**这是整机粒度**，不是按账号区分。若确认服务端 `writable: true` 却仍写不进，检查是不是踩了下面几条历史坑（已在 2026-11-04 的版本修复，若复现请上报）：

| 现象 | 原因 |
| --- | --- |
| 新建文件总是 0 字节，覆盖已有文件却正常 | 库对 `FILE_CREATE` 只给 `O_CREATE\|O_EXCL`，句柄只读，后续 WRITE 被拒 |
| 复制大文件进度走完却报“意外的网络错误” | 客户端先发 `SET_INFO` 的 `FileAllocationInformation` 预占空间，库不支持 |
| 删除/改名/改时间戳静默失效 | 包装层没转发 `Remover` / `SetInfoer` / `Renamer` 能力 |

**agent 不要自行改服务端配置**：`writable` 一改就是整个局域网（含匿名来宾）都能删文件。要改交给服务端维护者。

## 6. 445 不通

```powershell
Test-NetConnection 192.0.2.11 -Port 445
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -like '192.168.*' }
```

- 本机网段不在 `192.0.2.0/24` → 网关/路由问题，找网络管理。
- 同网段但 445 不通 → 大概率路由器开了 **AP 隔离**，或这台机器连的是访客 Wi-Fi。这类情况改注册表、跑 EXE 都无效，**不要继续修客户端**，直接上报网络层。
- 电视/手机能用、只有这台 Windows 不行 → 回到 §3。

## 7. 服务端自查（只在客户端手段都用尽时才做）

需要在 `192.0.2.11` 上有 ssh 账号（`example-user`）。以下命令只读，可以放心执行：

```bash
systemctl is-active fsgw                 # 期望 active
fsgw status | head -8                    # 期望 ALL，三个监听都"就绪"
sudo ss -lntp | grep -E ':445|:8200|:8443'
fsgw smb check                           # 期望"账号登录 共 N 个账号"
sudo journalctl -u fsgw -n 50 --no-pager | grep -E '会话已通过|拒绝|口令'
```

日志会直接告诉你客户端卡在哪：

- `SMB 会话已通过账号口令认证` `user:admin` → 认证成功，问题在别处
- `SMB 拒绝了未登记的客户端账号` → 这台机器的用户名不在账号表，或因 §9 的哈希坑被跳过
- `SMB 口令校验失败` → 账号对、口令错
- `SMB 会话按来宾放行` → 退到匿名（Win11 会接着被签名策略拦掉）

**改账号要重启**：`sudo systemctl restart fsgw`。

## 8. 验收清单

修完必须逐条打勾，任何一条不满足都不算修好：

```powershell
net use                                                     # 状态为 OK，指向 \\192.0.2.11\share
Test-Path Z:\                                               # True
(Get-ChildItem Z:\).Count                                   # 与服务端一致（当前 14 项）
[System.IO.File]::WriteAllText('Z:\_t.txt','ok')            # 不报错
Get-Content Z:\_t.txt; Remove-Item Z:\_t.txt                # 内容对、能删
```

再补一条只读页面（浏览器能开即算通过）：`http://192.0.2.11:8443/share/`，弹框填 `admin` / `changeme`。

**注意**：网页列表读的是服务端 SQLite 索引，不是实时文件系统，所以“从 Windows 删了文件、网页还显示”属于已知现象，不代表没写成功；以 SMB 侧（`Z:`）为准。

## 9. 已知坑（改配置/写脚本前先看）

1. **NT 哈希必须 32 位十六进制**。仓库里 `changeme` 的示例值曾少写两位（`000000000000000000000000000000`），正确是 `00000000000000000000000000000000`。`ParseNTHash` 失败时账号会被**静默跳过**：`fsgw smb check` 里看得到，登录却报“未登记”。生成用 `fsgw smb nt-hash <口令>`，别手抄。
2. **`.cmd` 注释只用 ASCII**，见 §4.4。
3. **Go 的 `os.ReadDir` 读不了这个共享**：内部走 `GetFileInformationByHandleEx(FileIdBothDirectoryInfo)`，服务端不支持，报 `The parameter is incorrect`。改用 `os.Open` + `Readdirnames(-1)`（EXE 里就是这么写的）。
4. **`net use` 输出首列是本地化状态词**（`OK`/`不可用`），不是盘符。解析盘符要在整行里找 `X:` token。
5. **重命名只在同目录内生效**（服务端只取 basename），跨目录请复制 + 删除。

## 10. agent 执行规约

**可以自动做**：诊断、清旧映射/旧凭据、存凭据、映射盘符、装 §4 的重连任务、跑验收。

**必须先问人再做**：

- 改服务端任何配置（`writable`、`guest_writable`、账号表、重启 fsgw）
- 改 `LmCompatibilityLevel` 之外的全局安全策略（本手册只授权这一项）
- 删除共享里的任何已有文件（只能删自己建的 `_t.txt` 之类的测试文件）

**不要做**：

- 不要为了“能连上”去关 SMB 签名校验（`RequireSecuritySignature=0` 之类）——那会同时削弱本机安全，且解决不了根因
- 不要把口令写进脚本文件长期留盘；用 `cmdkey` 存进 Credential Manager
- 不要把 `admin / changeme` 这类共享口令发到群聊或提交进仓库

**上报格式**（修不好时按这个发，能大幅缩短排查）：

```
机器名 / 登录用户 / 本机 IP：
445 是否通：
UNC 直连结果（成功列几项 / 报什么错）：
Z: 当前状态：
cmdkey 里有没有 192.0.2.11：
错误码原文：
已执行的步骤与结果：
```

## 12. 可复制给 agent 的指令

目标机器上没有这个仓库时，把下面整段贴给它的 agent 即可（内容自包含）：

```text
请修复本机访问 Windows 共享盘 \\192.0.2.11\share 的问题，目标是盘符 Z: 能读能写。

背景事实（不要重新推导）：
- 服务端是 Debian 上的纯 Go SMB2/3 服务端，共享名 share，可读写，账号 admin / changeme。
- Win11 24H2+ 强制 SMB 签名，来宾会话签不了名，所以必须用账号登录，不要靠放开来宾。
- 常见故障是开机后 Z: 停在"不可用"：Windows 登录时恢复映射，网络没就绪就失败且不重试。

按顺序执行：
1. 诊断，先别改东西：
   net use; (cmdkey /list:192.0.2.11); Test-Path 'Z:\'
   Test-NetConnection 192.0.2.11 -Port 445
   试直连： [System.IO.Directory]::GetFileSystemEntries('\\192.0.2.11\share')
2. 若 445 不通 → 停止，报告"网络层不通，疑似 AP 隔离或不在 192.0.2.0/24"，不要改注册表。
3. 若 UNC 直连正常、只有 Z: 不可用 → 执行：
   net use Z: /delete /y; net use Z: \\192.0.2.11\share /persistent:yes
4. 若连 UNC 都失败 → 依次执行（需管理员）：
   Set-NetConnectionProfile -NetworkCategory Private
   Set-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Services\LanmanWorkstation\Parameters' -Name AllowInsecureGuestAuth -Value 1 -Type DWord
   Set-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\Lsa' -Name LmCompatibilityLevel -Value 3 -Type DWord
   net use * /delete /y; cmdkey /delete:192.0.2.11
   cmdkey /add:192.0.2.11 /user:admin /pass:changeme
   net use Z: \\192.0.2.11\share /persistent:yes
5. 装开机自动重连（防止重启后复发）：
   在 %LOCALAPPDATA%\fsgw-reconnect\reconnect.cmd 写一个脚本：先 dir Z:\ 判断能否用，
   能就 exit /b 0；不能就 net use Z: /delete /y，然后循环最多 12 次
   net use Z: \\192.0.2.11\share /persistent:yes，每次间隔 5 秒。
   注释只能用 ASCII（中文会被 GBK 代码页切错）。
   再用 Register-ScheduledTask 注册 AtLogOn 触发、延迟 20 秒、RunLevel Limited 的计划任务，
   任务名"共享盘自动重连"。
6. 验收，四条都要过：
   net use 显示 OK；Test-Path Z:\ 为 True；(Get-ChildItem Z:\).Count 与预期一致；
   写一个 _t.txt 再读回、删掉都不报错。

禁止：
- 不要关闭 SMB 签名校验（RequireSecuritySignature=0）来解决，解决不了根因还会削弱本机安全。
- 不要修改服务端任何配置（writable / 账号表 / 重启服务），需要改就停下来报告。
- 不要删除共享里已有的任何文件，只允许删自己创建的测试文件。

修不好时按这个格式报告：
机器名 / 登录用户 / 本机 IP / 445 是否通 / UNC 直连结果 / Z: 状态 /
cmdkey 是否存在该目标 / 错误码原文 / 已执行的步骤与结果
```
