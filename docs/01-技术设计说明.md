# 01 技术设计说明

## 1. 文档定位

本文把策略讨论稿翻译成可编码的工程设计。策略层的共识（局域网直读直写、外部只读、SQLite 唯一真相源、移动零版本、开关即安全）全部继承，不再重复论证；本文只回答"具体怎么实现"以及"哪些地方做不到"。

三处工程调整及其理由收敛在 `04-决策点与风险登记.md`，本文在涉及处标注决策编号，例如 `[D-02]`。

## 2. 目标与非目标

### 2.1 第一版目标

- 局域网内电视、手机、PC 免装 App 访问 `D:\share`，可读可写
- 外部（公网或隧道）只读浏览与下载，含历史版本
- 文件整理（移动、重命名、建目录）不产生版本链增长
- 网关关闭后本机不残留任何监听端口与防火墙放行规则
- 索引与磁盘不一致时可自愈，且自愈过程不扫全盘
- 提供本机网页控制台（HTML 前端 + Go 后端）：开关、共享目录、索引统计、诊断与审计在一个页面上闭环

### 2.2 非目标

- 不做多用户、角色、ACL 体系。外部面一个共享口令，局域网面匿名或单账户
- 不做块级快照、不做全量备份、不做 Git 式分支
- 不做跨平台一致的 SMB 协议栈自研（见 D-01）
- 不做云端同步、不做去重存储引擎
- 不做远程管理界面。控制台只绑回环，不提供"从手机管理网关"的能力
- 不做移动端 App、不做托盘常驻 UI（控制台就是唯一图形界面，浏览器即宿主）
- 不接管系统盘与用户主目录，共享根只能是显式配置的目录白名单

## 3. 架构总览

```
                    ┌──────────────────────────────────────────────┐
                    │              fsgw 单进程（LocalSystem）       │
                    │                                              │
  电视 / 手机 ──SMB──▶  smbhost  ─┐                                │
  电视 ────────DLNA─▶  dlna     ─┤                                │
                    │            ├──▶ vfs ──▶ index(单写队列) ──▶ SQLite(WAL)
  外部 ───────WebDAV─▶ webdav  ─┘        │                        │
                    │                   ▼                        │
                    │              D:\share (字节仓库)             │
                    │                   │                        │
                    │   watcher ────────┘                        │
                    │      │                                     │
                    │      └──▶ 事件分类 → 索引更新 / 移动配对 / 快照捕获
                    │                                              │
                    │   ctlapi (127.0.0.1:8444) ──▶ 开关状态机      │
                    │      ▲            │            │            │
                    │      │        webui(embed)   firewall       │
                    └──────┼───────────────────────────────────────┘
                           │
              浏览器控制台 ──┘   （fsgw CLI 走同一 API）
```

关键不变量：

1. **数据库是唯一真相源**。目录列举、`Stat`、路径解析一律查库，不 `os.Stat`。
2. **磁盘只提供字节**。读取失败如实报错，不反向修正数据库。
3. **写路径要么入库要么不可见**。结构性变更走事务，提交后才对外生效。
4. **SMB 来源与网关来源互斥**。网关自己经手的写操作同步更新库，并抑制对应 fsnotify 事件，避免重复记账。

## 4. 进程与生命周期

单进程，无外部依赖（SQLite 嵌入、纯 Go 驱动、CGO 关闭）。

运行形态：

| 形态 | 用途 | 权限 |
| --- | --- | --- |
| `fsgw`（无参数） | 双击 exe 的默认路径：`run -detach -open`，UAC 提权后转后台 | 自动申请管理员 |
| `fsgw run` | 前台 console，开发调试与验收用 | 自动申请管理员；`-noelevate` 关掉 |
| `fsgw service install/start/stop` | 注册为 Windows 服务（`x/sys/windows/svc`），开机自启 | LocalSystem |
| `fsgw on / off / status` | 控制面客户端，向运行中的进程投递指令 | 普通用户（走回环 HTTP API + token，见第 11 节） |
| `fsgw stop` | 优雅退出：拆干净暴露面再结束进程 | 普通用户（同上） |
| `fsgw ui` | 生成带 token 的地址并打开默认浏览器 | 普通用户 |

启动语义（Windows）：

- **无参数即 `run`**：`fsgw`、`fsgw -notray` 这类写法不再报"未知命令"，
  一律当成 `run` 的参数处理，因为最容易忘的就是子命令。
- **自动提权**：`run` 发现当前令牌不是管理员，就用 `ShellExecuteW(verb="runas")`
  重新拉起自己；转后台时把新进程的窗口设成 `SW_HIDE`，桌面不留黑框。
  提权参数串由 `elevateParams()` 生成并有单元测试钉住——拼错的表现是
  "UAC 之后什么都没发生"，最难排查。
- **不占终端**：`-detach` 通过 `SpawnDetached` 拉起脱钩子进程
  （`DETACHED_PROCESS|CREATE_BREAKAWAY_FROM_JOB`，Job 不允许 breakaway 时降级），
  父进程打印控制台地址后立刻退出。
- **单实例**：启动前先探控制台端口的 `/healthz`（免令牌），已在跑就直接打印地址返回，
  所以双击多次不会出现第二个实例抢端口。

退出语义：`OFF` 与"进程不存在"必须都是零暴露。
因此 `POST /api/quit`（托盘「退出程序」、控制台按钮、`fsgw stop` 共用）与 `Ctrl+C`
走同一条 `Quit()`：停 WebDAV → 停 DLNA（发 SSDP byebye）→ 删 SMB 共享 →
清 `FSGW-` 防火墙规则 → `state.json` 写 `OFF` → 关闭 `quitCh` 主循环退出。
`Close()` 里再兜一次：只要 `applied != OFF` 就补拆，避免任何路径漏掉清理。
`fsgw stop` 在控制面不响应时退化为 `taskkill`，并显式告知"强杀不会清理
SMB 共享与防火墙规则，下次启动会自动清理"。

启动序列：

```
读配置 → 校验（路径存在、可写、非系统目录）→ 打开 SQLite → 迁移
  → 加载共享白名单 → 加载 desired_state（默认 OFF）
  → 若 desired_state != OFF：按状态机执行开启（失败则回落到 OFF 并告警）
  → 启动 watcher（ON/OFF 都跑，索引需要持续维护）
  → 启动 ctlapi（127.0.0.1:8444，内嵌 webui 静态资源）
```

注意：**索引维护与开关解耦**。开关只影响"对外暴露的协议面"，索引始终运行；否则每次开启都要重扫。

## 5. 开关状态机

### 5.1 状态定义

| 状态 | SMB 445 | DLNA (1900/8200) | WebDAV | 防火墙规则 |
| --- | --- | --- | --- | --- |
| `OFF` | 停 | 停 | 停 | 全部移除 |
| `LAN` | 开 | 开 | 停 | SMB + DLNA |
| `WAN` | 停 | 停 | 开 | WebDAV |
| `ALL` | 开 | 开 | 开 | 全部 |

### 5.2 转换顺序（不可调换）

开启方向，从外到内以避免"端口开了但服务没起"的窗口：

1. 校验目标状态的前置条件（共享根可读、端口未被占用、证书存在）
2. 创建防火墙规则（幂等：先删同名再建）
3. 启动对应 listener，等待就绪探针
4. 自检：本机连一次自己的端口，失败则回滚
5. 持久化 `desired_state`，写审计

关闭方向，从内到外：

1. 停止 listener（等待在途连接最多 5s，超时强制）
2. 移除防火墙规则
3. 持久化 `desired_state=OFF`，写审计

任一步失败：执行反向清理，最终状态回落到 `OFF`，并把失败阶段写进 `state.json.last_error`，控制面 `status` 直接展示。**不允许停在中间态。**

### 5.3 崩溃恢复

`state.json` 记录 `desired_state` 与实际 `applied_state`。进程启动时若二者不一致，一律按 `OFF` 启动并告警，不猜测用户意图。这样即使上次是异常退出，也不会有端口残留。

## 6. 平台抽象层

四个接口，Windows 实现优先落地，Linux 只留空实现（编译可通过、运行返回 `ErrNotImplemented`）。

### 6.1 fileid

```go
type FileID struct {
    VolumeSerial uint32
    ID           [16]byte // FILE_ID_INFO 的 128 位；退化路径时高 8 字节为 0
}

type Provider interface {
    Of(path string) (FileID, error)
}
```

Windows 实现要点：

- `CreateFileW` 打开句柄，目录必须带 `FILE_FLAG_BACKUP_SEMANTICS`，文件带 `FILE_FLAG_OPEN_REPARSE_POINT` 防止跟随符号链接与目录联接
- 优先 `GetFileInformationByHandleEx(FileIdInfo)` 取 128 位 ID 与卷序列号
- 不支持时退化为 `GetFileInformationByHandle` 的 `nFileIndexHigh/Low`（64 位），此时高 8 字节补零，并在 `objects.native_file_id` 里用 `v1:` 前缀区分，避免与 128 位 ID 冲突
- 句柄必须在取完 ID 后立即 `CloseHandle`，监听热路径上这是主要开销，量级约数十微秒，可接受

### 6.2 watcher

```go
type Op int // Create | Write | Rename | Remove

type Event struct {
    Op      Op
    Path    string // 绝对 Windows 路径（长路径已加 \\?\ 前缀）
    OldPath string // 仅 Rename 有效
    IsDir   bool
}

type Watcher interface {
    Add(root string) error
    Events() <-chan Event
    Overflow() <-chan string // 缓冲溢出，携带需要范围重建的子树根
    Close() error
}
```

Windows 实现要点（不依赖第三方递归封装，直接调 `ReadDirectoryChangesW`）：

- `bWatchSubtree=TRUE`，`FILE_NOTIFY_CHANGE_FILE_NAME | DIR_NAME | SIZE | LAST_WRITE | CREATION`
- 缓冲区 64 KiB，单缓冲轮转；溢出返回 `ERROR_NOTIFY_ENUM_DIR` 时向 `Overflow()` 投递该子树根
- 重命名天然成对：`FILE_ACTION_RENAMED_OLD_NAME` 紧跟 `FILE_ACTION_RENAMED_NEW_NAME`，无需像 inotify 那样靠 cookie 配对，但仍要处理"只收到一半"的情况（见 `02` 的 pending_moves）
- 事件只给路径不给 ID，因此每个事件都要开一次句柄取 `FileID`。删除事件无法取 ID，只能用路径匹配库中记录

### 6.3 firewall

```go
type Rule struct {
    Name    string // 统一前缀 FSGW-
    Dir     string // in
    Action  string // allow
    Proto   string // tcp | udp
    LocalPort  int
    RemoteIP   string // localsubnet | any
    Profile    string // private | domain,private
}

type Firewall interface {
    Ensure(rules []Rule) error
    RemoveByPrefix(prefix string) error
    List(prefix string) ([]Rule, error)
}
```

实现走 `netsh advfirewall firewall`，理由：命令可审计、可回滚、失败信息明确，比 COM 的 `INetFwPolicy2` 更容易定位问题。每条规则的创建形式为 `delete rule name=X` 后 `add rule`，保证幂等。

### 6.4 link

```go
type Linker interface {
    Hardlink(oldPath, newPath string) error // 同卷：CreateHardLinkW
    Copy(src, dst string) error             // 跨卷退化
    SameVolume(a, b string) (bool, error)
}
```

## 7. 索引与监听

### 7.1 事件分类

事件进入后先做归属判断，再分流。这一步决定了后面所有语义是否正确。

| 事件来源 | 判定方式 | 处理 |
| --- | --- | --- |
| 网关自身（WebDAV 写、快照、清理） | 写入前在 `suppress` 表登记 `(路径, 期望 mtime/size)` | 直接丢弃，不做任何记账 |
| SMB 客户端写入 | 路径在 SMB 共享白名单内且未登记 suppress | 归为 `source=smb`，走 best-effort 快照 |
| 本机应用直接修改 | 其余 | 归为 `source=local`，只保证索引版本链 |

`suppress` 表的键包含期望的 mtime 与 size：只有实际事件与预期一致才丢弃，避免把"网关写完但用户同时也在改"的情况误吞。

### 7.2 防抖与合并

- 结构性变更（Create / Rename / Remove）：100–200ms 窗口，保证移动配对完整
- 内容变更（Write）：300–500ms 窗口，同一文件窗口内多个 Write 合并为一次版本追加
- 大文件写入会产生持续 Write 事件流。策略：当同一 `FileID` 的 Write 事件间隔小于 500ms 时持续续期，直到静默满窗口才落一次版本；期间状态为 `writing`，`ReadDir` 可见但标记为"写入中"

### 7.3 溢出与漏事件

溢出不等于需要全盘扫描。处理方式：

1. 从 `Overflow()` 拿到子树根
2. 对该子树做**一次范围重建**：`ReadDir` 递归遍历（限制最大深度与节点数，超限则跳过并告警）
3. 与库中该子树的记录做差集，补插、改删，全部在一个事务内完成
4. 记录 `reconcile` 审计事件，含耗时与节点数

另外提供低频校验任务（默认每 6 小时，仅对最近 24 小时内变更过的 `object` 抽查存在性），兜住监听启动前与半途漏掉的事件。

### 7.4 写入顺序

见 `02-数据模型与事务.md` 第 4 节。这里只强调一条：**先库后可见**。结构性变更事务提交前，新路径不出现在任何 `ReadDir` 结果里。

## 8. VFS 与路径

VFS 是三个协议面的公共下层，负责三件事：路径规范化、白名单校验、穿越防护。

规范化规则：

- 输入一律转绝对路径，扩展为 `\\?\` 长路径形式（超过 240 字符必须）
- 统一分隔符为 `\` 落盘、`/` 入库存 `path_key`
- Windows 大小写不敏感：`path_key = lower(path)`；显示名保留原始大小写。配置项 `case_sensitive` 默认为 `false`
- 拒绝并记录以下输入：含 `..` 段、含 ADS 冒号（`file.txt:stream`）、含设备名（`CON`、`NUL`、`COM1` 等）、末尾带空格或点、路径长度超限
- 解析软链接与目录联接：解析后的真实路径必须仍在共享根内，否则拒绝

白名单校验走 `share_dirs` 表：一次查库判定 `(share_id, rel_path)` 的最长前缀，命中才放行。可写性继承：子目录默认继承父级，允许显式覆盖为只读。

## 9. 局域网面

### 9.1 SMB：自研服务端优先，抢不到 445 回退系统共享

早期版本不自研 SMB 协议栈（理由见 D-01），直接托管 Windows 原生共享。Win11 24H2 起
客户端强制签名，来宾会话签不了名，免密只能靠整机 `ForceGuest`——这条路走不通，于是
Windows 侧改成与 Linux 同一套的进程内 Go SMB2/3 服务端（`smb.engine: auto`）：认证在进程内做，
免密与账号并存。自研服务端要在 Windows 上对外提供服务，必须先从 `LanmanServer` 手里接管 445。

**接管失败是正常分支，不是异常**：实测部分机器停掉 `LanmanServer` 后 445 仍被 PID 4（System，
`srv2` 内核驱动）占着不释放。此时的处理：

- 6 秒宽限仍拿不到 → 还原系统服务启动类型并重新拉起，日志写明占用者；
- 记 `<data_dir>\port445_blocked.json`（按开机时刻），同一开机内不再重复停系统共享；
- `auto` 下把本进程引擎切成 `native`，改用系统共享 + 系统来宾模式，状态如实标注"已就绪 · 免密可读写"；
- 免密失败只降级为"需账户口令"，不把整个 SMB 面标成失败。

下面这些是 native 路线（也是本机实际在用的路线）的免密前提：

- 用 `net share share=D:\share /grant:...` 创建/更新共享，名称固定为 `share`
- 只启用 SMB2/3：`Set-SmbServerConfiguration -EnableSMB1Protocol $false`
- **免密（来宾）登录不是"放行一个权限"就行**，它要求六条同时成立，缺一不可：

| # | 开关 | 实现 | 缺了会怎样 |
| --- | --- | --- | --- |
| 1 | 内置 Guest 账户启用 | `net user Guest /active:yes` | 没有可映射的主体，`NT_STATUS_ACCESS_DENIED` |
| 2 | 来宾模式 | `HKLM\SYSTEM\CurrentControlSet\Control\Lsa\ForceGuest=1` | 客户端仍被要用户名口令 |
| 3 | 共享权限含 Everyone | `net share ... /grant:Everyone,READ` | 会话建立后在共享层被拒 |
| 4 | NTFS 授权 | `SetNamedSecurityInfoW` 给根目录加 `Everyone:(OI)(CI)` | 共享放行了、文件系统拦下 |

- 第 4 条的实现细节值得单独说：**不用 `icacls`**。`icacls <root> /grant` 会就地把可继承 ACE
  传播到整棵子树，几十万文件的目录实测要跑十几分钟；用 Win32 安全 API 只读写根对象的
  安全描述符，语义一样但调用路径短得多（`internal/smbhost/acl_windows.go`）。
  代价是**传播本身省不掉**——Windows 的继承 ACE 是物化的，子对象必须逐个更新，
  五十万文件实测 889 秒。所以这一步放在后台 goroutine 里跑，开关切换不等它：
  SMB 面先起来（账号口令可进），免密权限随后补齐，控制台显示「正在设置免密目录权限」。
- **换共享根必须重新授权**。NTFS 授权是按路径打的，换了目录不补一次，
  现象是「Guest 能登录、列目录全是 `ACCESS_DENIED`」——会话建起来了，文件系统拦住。
  同理，中途被强杀会留下"根目录有 ACE、子对象没传播完"的半成品，
  所以判据不能用"根目录有没有 Everyone"，而要用 `data/guest_acl.json` 这个完成标记；
  标记不在就整条重跑（`SET_ACCESS` 幂等，重复只会补齐没传播到的部分）。
| 5 | Guest 不在「拒绝从网络访问」 | LSA 账号权限，`LsaRemoveAccountRights(SeDenyNetworkLogonRight)` | `NT_STATUS_LOGON_TYPE_NOT_GRANTED` |
| 6 | 允许空密码账户网络登录 | `HKLM\...\Lsa\LimitBlankPasswordUse=0` | `STATUS_ACCOUNT_RESTRICTION` |

- 第 5、6 条是最容易漏的：它们是**安全策略**，既不在共享权限里、也不在 NTFS 里。
  Windows 客户端版默认把 Guest 放进「拒绝从网络访问这台计算机」，Guest 账户又没有密码，
  而默认策略禁止空密码账户从网络登录——两条任意一条成立，前四条配得再对也连不上，
  且报错看起来都像"权限不足"。第 5 条必须用 LSA API 改（`secedit`/`reg` 在受限环境下不可用），
  改完要重新枚举一次复核：LSA 参数错位不会报错，只会"看起来成功"。

- 走的是**来宾模式**，不是 null session：Windows 10/11 上匿名会话（`RestrictNullSessAccess`、
  `NullSessionShares`）对文件共享基本走不通，而那套设置还会顺带扩大其它攻击面。
  来宾模式的实际语义是——客户端**不带凭据、或者带任意凭据**，服务端一律映射为 Guest。
- `ForceGuest` 是**整机**设置：打开期间，本机所有本地账户的网络登录都会被映射为 Guest。
  所以 `guest` 与 `account` 无法在同一台机器上并存，`both` 在系统层面等同于 `guest`
  （配置仍接受 `both`，行为按 `guest` 处理，避免老配置报错）。
- `smb.auth` 三种取值与真实行为：

| 模式 | 实际行为 | 适用 |
| --- | --- | --- |
| `account`（默认） | 经典模式，必须用本机账户口令 | iOS「文件」、Windows 资源管理器 |
| `guest` | 启用上述四条，局域网内免密直进 | 安卓电视、手机、DLNA 之外的兼容退路 |
| `both` | 等同 `guest`（ForceGuest 无法按共享拆分） | 仅为兼容旧配置保留 |

- 免密默认**只读**（`smb.guest_writable: false`）：电视只是播放，不该有删文件的权限。
  注意来宾模式下连管理员经 SMB 也会被映射为 Guest，要写入必须显式打开这个开关。
- 改动前的系统状态记在 `data/smb_guest_backup.json`（Guest 原启用状态、ForceGuest 原值、
  Everyone 原本是否有权限、Guest 原本是否在拒绝名单、`LimitBlankPasswordUse` 原值）。
  `OFF` / 退出时按备份还原；若进程被强杀，下次以 OFF 启动时补还原。
  备份只在第一次写入——崩溃重启后系统已处于免密态，覆盖备份会让"最初的样子"永久丢失。
  复用旧备份时仍会重跑 `EnsureGuestLogon()`，因为系统策略可能被重启或组策略刷新回去。
- 还原失败时**保留备份**并在下次启动重试，不会出现"关掉了但策略还开着"却无人处理的情况。
- 客户端侧：Windows 10 1903+ 作为客户端默认拒绝来宾共享（`AllowInsecureGuestAuth=0`），
  报"组织的安全策略阻止未经身份验证的来宾访问"。这是**客户端**设置，与服务端无关，
  需要时用 `fsgw smb client-guest on` 单独打开。
- 内核 cifs 的 `-o guest` 走"纯匿名会话"（无 NTLMSSP 负载），Windows 在 SessSetup 阶段就拒；
  而 Samba 客户端与 Windows 客户端都能进。这不是服务端缺陷，客户端改用
  `-o username=Guest,password=` 即可（任何用户名在来宾模式下都会映射为 Guest）。
- 自检用 `fsgw smb check`：逐项打印上面六条的现状，而不是只回一句"连不上"。
  其中读取 LSA 账号权限需要管理员，非提权时该行明确显示"读不到"，**不报 OK**——
  否则诊断会假绿，比不检查更糟。

账户模式的硬约束：Windows 默认策略禁止空密码账户远程登录（`LimitBlankPasswordUse=1`），所以口令不能为空，必须是真实密码。

### 9.2 写路径的能力边界

托管系统共享意味着**网关不在写入路径上**，这是 D-01 的直接代价。后果：

- 无法在覆盖前硬链接旧内容，内容快照降级为 best-effort（见 `02` 第 6 节）
- 写事件由 `ReadDirectoryChangesW` 事后送达，索引版本链不受影响（仍然准确），只有内容快照的承诺打折
- 想恢复"写前捕获"，只有三条路：自研协议栈、写内核 minifilter、定时 VSS 快照，见 D-02

### 9.3 DLNA

- 纯 Go DMS，指向 `media=true` 的白名单目录，只做发现与播放，不暴露文件管理
- SSDP 多播用 `239.255.255.250:1900`，HTTP 服务用可配置高端口（默认 8200），避免与 SMB 抢权限
- **多网卡机器必须按网卡各报各的地址**。Windows 上装了 Hyper-V / VMware / WSL 之后会多出
  `172.x` 的虚拟交换机，且常排在物理网卡前面；早期版本按"第一个私网地址"挑，
  于是把 `172.31.208.1` 当 LOCATION 宣告出去，电视去拉这个跨网段地址必然超时——
  现象是「DLNA 显示已广播，电视里就是没有」，Linux 单网卡机器上不会复现。
  现在的做法：每块网卡一个 socket，`M-SEARCH` 应答和 `NOTIFY` 都用**收到包的那块网卡地址**
  拼 `LOCATION`；界面展示的 IP 则按路由表选默认出口，并跳过虚拟网卡名。
- **设备 UDN 必须"同机稳定、异机唯一"**。UDN 是 SSDP 的去重键，客户端按它判断
  "这是不是同一台设备"。早期实现 `UDN = md5(名称 + 端口)`，而 Windows 版与 Linux 版
  默认配置都是 `家庭共享:8200`，两台机器因此宣告**同一个 UUID**，`rootDesc.xml` 也逐字节相同；
  客户端（小米电视）按 UUID 去重只保留一台（先应答/先缓存的，通常是 Linux 那台），
  表现就是"Linux 的能在电视上看到，Windows 的死活看不到"。
  现在改为 `<data_dir>/dlna_udn.txt` 里落盘的随机 UUID（v4，首次生成后复用），
  文件损坏或目录只读时退化为「主机名 + 首个 MAC」派生值，仍然是本机独有。
- 媒体类型白名单：视频、音频、图片；不索引文档与压缩包
- 小米电视自带播放器可零安装发现；同时保留 SMB 路径作为兼容退路（部分电视 DLNA 只认 MP4）

## 10. 外部只读面

### 10.1 WebDAV

- 基于 `golang.org/x/net/webdav`，包装一层方法白名单 handler：只放行 `GET`、`HEAD`、`PROPFIND`、`OPTIONS`；其余（`PUT`/`DELETE`/`MKCOL`/`MOVE`/`COPY`/`PROPPATCH`/`LOCK`）返回 `405` 并记审计
- `PROPFIND` 走 index 查库返回属性，不触碰磁盘
- `GET` 先查库确认存在与大小，再回源读字节流；支持 `Range`，支持 `ETag`（用 `content_hash`，未算哈希时用 `mtime-size` 合成）
- 路径映射：当前视图 `/share/...`，历史视图 `/versions/...`，两者都只读
- 认证：HTTP Basic，口令 bcrypt 存配置；单口令全局生效，可选 per-share 口令
- 默认绑定 `127.0.0.1:8443`，公网暴露靠反向代理或隧道（Cloudflare Tunnel / Tailscale / frp）。**设计上不提供"直接监听 0.0.0.0:443"的一键选项**

### 10.2 目录列举的性能账

`ReadDir` 直查 SQLite 不设内存缓存，这是讨论稿的明确选择。代价与缓解：

- 单目录 1 万文件：`SELECT ... WHERE parent_path=? ORDER BY name_key` 走 `(parent_path, name_key)` 复合索引，配合覆盖索引可到毫秒级
- 电视 SMB 客户端会频繁列举同一目录。缓解：协议层允许短暂的"同一路径 500ms 内重复列举"复用结果，但**这是协议层的短生命周期快照，不是索引缓存**，不引入失效问题

## 11. 控制台：前端 HTML，后端 Go

### 11.1 形态

控制台是网关的用户交互面，与三个协议面并列，但边界更严格：**只在本机回环上运行，永不暴露给局域网或公网**。

| 层 | 选型 | 约束 |
| --- | --- | --- |
| 前端 | 原生 HTML + CSS + 原生 JS，单页 | 无 npm、无构建步骤、无 CDN 依赖（断网可用），`embed.FS` 打进二进制 |
| 通信 | `fetch` + `EventSource`（SSE） | 变更一律 POST + 自定义头，不用 GET 改状态 |
| 后端 | Go 标准库 `net/http` + Go 1.22 的 method-aware `ServeMux` | 零第三方框架 |
| 监听 | `127.0.0.1:8444` | 与 WebDAV 的 8443 用**两套独立 mux 与中间件**，不共用路由 |

不用 Electron / WebView2 的理由：它引入第二套运行时、升级链路和签名问题，而控制台需要的全部能力浏览器都有。代价是没有系统级文件选择框，靠 11.6 的目录浏览接口补上。

CLI 与 UI 共用同一个 HTTP API，不再单独实现命名管道：

```
浏览器 UI ─┐
           ├─▶ 127.0.0.1:8444 /api/*  ──▶ app 状态机 ──▶ 平台层
fsgw CLI  ─┘        （token 鉴权）
```

这样"开关"只有一条实现路径，验收也只需要验一处。

### 11.2 界面结构

单页五块，从上到下按"危险程度递增、使用频率递减"排列：

| 区块 | 内容 | 说明 |
| --- | --- | --- |
| 总开关 | 四态分段控件（OFF / LAN / WAN / ALL）+ 当前状态徽标 + 一键全关 | 全关按钮独立配色，需二次确认 |
| 服务面 | SMB / DLNA / WebDAV 三张卡：监听地址、就绪状态、复制连接串（`smb://192.168.x.x`、`https://…`） | 连接串可直接发给手机 |
| 共享目录 | 白名单列表、只读/媒体标记、增删与「更换目录」入口 | 增删与换根都走目录浏览接口选择；换根当场写回配置并重建索引 |
| 索引与快照 | 文件数、待处理事件、写队列深度、最近重建；快照占用、版本数、配额条、清理按钮 | 带 sparkline（手写 SVG，不引图表库） |
| 诊断与审计 | 匿名 SMB 客户端策略、445 占用、磁盘空间、防火墙规则状态；最近审计日志（可筛选"拒绝"） | 把 D-03 那类"连不上但不是 bug"的问题前置暴露 |

### 11.3 API 一览

所有接口前缀 `/api`，均需登录会话或 token（`/api/login`、`/api/logout`、`/api/whoami` 除外）。变更类返回 202 + `operation_id`（开关是长任务，不能用一次请求的成败表示）。

| 方法 | 路径 | 用途 | 备注 |
| --- | --- | --- | --- |
| POST | `/api/login` | `{username,password,remember}` → `fsgw_sess` cookie | 免 token，校验共享账号；失败 5 次锁 60 秒 |
| POST | `/api/logout` | 清会话 | 免 token |
| GET | `/api/whoami` | 当前登录用户 / 401 | 免 token，前端启动时探一次 |
| GET | `/api/status` | 状态快照：四态、各面就绪、索引统计、快照占用 | 前端首屏 |
| GET | `/api/events` | SSE 推送：状态变化、队列深度、日志尾 | 2s 心跳 |
| POST | `/api/switch` | `{state:"OFF\|LAN\|WAN\|ALL"}` | 二次确认字段 `confirm` |
| GET | `/api/operations/{id}` | 长任务进度与失败阶段 | 失败带 `stage` |
| GET | `/api/config` | 脱敏配置（口令、hash 一律打码） | |
| PUT | `/api/config` | 校验后原子写回（临时文件 + rename） | 需重启的字段标 `requires_restart` |
| GET/POST/DELETE | `/api/shares` | 白名单增删 | 删除共享需 `confirm` |

| PUT | `/api/dlna/name` | `{name}` 改 DLNA 设备名 | 非空、≤32 字符；写回 `dlna.friendly_name`（行内替换），重启 DLNA 重播 byebye/alive，UDN 不变 |
| POST | `/api/index/reconcile` | 子树重建 | 只接受已配置共享内的路径 |
| GET | `/api/fs/list` | 列目录（仅子目录名 + 可写标记） | 见 11.6 |

| GET | `/api/audit` | 审计分页查询 | `since`、`limit`、`result` |
| GET | `/api/diagnose` | 一次性体检 | 匿名策略、端口、磁盘、防火墙 |

### 11.4 本地网页的真实威胁：CSRF 与 DNS rebinding

控制台跑在 `127.0.0.1`，这不等于安全。用户浏览器里的任何网页都能向 `http://127.0.0.1:8444` 发起请求；DNS rebinding 还能让攻击者域名解析到回环地址，从而绕过同源限制读取响应。控制台一旦被第三方页面驱动去开 `ALL`，等于把共享直接推到公网。

四道防线，缺一不可：

1. **登录凭据**，两条通道并存：
   - **人**：`POST /api/login` 提交用户名 + 口令，校验的是**共享账号**（`webdav.username`/`webdav.users[]` 的加盐摘要、`smb.account_name` 的明文或 NT 哈希、`smb_clients.yaml` 里登记的客户端）。通过后发 `fsgw_sess` 会话 cookie：`HttpOnly`（JS 读不到）、`SameSite=Strict`、无 `Secure`（控制台是明文 HTTP）；服务端会话表落盘 `<data_dir>/ui-sessions.json`（`0600`），默认 7 天，服务重启不掉线。同一来源连续失败 5 次锁 60 秒。为什么复用共享账号：控制台与共享目录是同一个使用者、同一批权限，另立一套账号只会多一个"这台机器该用哪个口令"的问题。
   - **机器**：`data/control.token`，首次启动生成 24 字节随机值（48 位十六进制），写入时限定当前用户 ACL（`0600`）。前端取 token 有三条路，按优先级：URL fragment（`#token`，不进 `Referer`、不进服务端日志）→ `?token=`（给命令行/预览面板）→ 本机存储（`localStorage`，勾了"记住"才有；否则 `sessionStorage`）。之后每个请求带 `X-FSGW-Token`（SSE 用 `?token=`，因为 `EventSource` 不能设头），服务端用 `crypto/subtle.ConstantTimeCompare` 比对。`fsgw ui` 与所有脚本走这条，行为不变。
   
   页面启动时先打 `GET /api/whoami`：200 直接进面板，401 才弹登录框（口令登录为主，令牌收在折叠区）。带 token 打开时跳过 whoami 直接验 `/api/status`。
2. **Origin 校验**：`Origin` 必须为空，或与"HOST 白名单里的某个名字 + 当前端口"同源，否则 403。登录接口同样过这关——否则任何网页都能把用户的口令"代为提交"。
3. **Host 校验**：`Host` 必须是白名单里的名字，端口必须等于监听端口。白名单 = 回环（`127.0.0.1`/`localhost`/`::1`）+ 本机各网卡 IP + `ui.allowed_hosts`。这是防 DNS rebinding 的关键一步——攻击者域名解析到本机 IP 后，`Host` 头仍是攻击者域名，直接被拒；而"放行字面 IP"不会削弱这条防线
4. **监听范围显式化**：`ui.bind` 默认 `127.0.0.1:8444`；要绑非回环地址必须同时写 `ui.allow_remote: true`，配置校验会拦下"顺手改成 0.0.0.0 却忘了这是暴露面变化"
5. **不回 CORS 头**，且变更接口要求自定义头。跨源带自定义头的请求会先发 preflight，我们不应答 `Access-Control-Allow-*`，请求根本到不了业务逻辑

补充：`GET /api/fs/list` 与 `/api/audit` 同样要鉴权，不要因为"看起来是只读"就放过——它们能泄漏本机目录结构。

### 11.5 长任务与状态推送

开关一次要动防火墙、起停监听、自检，不是一次请求能同步完成的：

- `POST /api/switch` 立即返回 202 与 `operation_id`，实际执行在后台 goroutine
- 进度与失败阶段通过 SSE 推给前端，同时 `GET /api/operations/{id}` 可主动查询
- 失败时的 `stage` 直接对应 5.2 的五步，前端展示"卡在创建防火墙规则"，而不是笼统的"操作失败"

### 11.6 前端拿不到本地路径，所以需要目录浏览接口

浏览器出于安全不提供本地绝对路径，`<input type="file" webkitdirectory>` 只给相对路径。要"添加共享目录"就必须由后端列目录：

```
GET /api/fs/list?path=D:\
→ {"path":"D:\\","entries":[{"name":"share","is_dir":true},{"name":"backup","is_dir":true}]}
```

约束，全部在实现里硬编码，不做成配置：

- 只返回**子目录**，不返回文件名、不返回大小、不返回内容
- 只接受盘符根（`D:\`）或已配置共享根下的路径，拒绝 `..`、拒绝 UNC（`\\host\share`）
- 路径规范化复用 `internal/vfs`，与协议面同一套规则，不另写一份
- 每次调用写审计（谁在什么时候浏览了哪个目录）

### 11.7 危险操作的产品层保护

技术防线之外，交互层也要拦一次：

- 四态开关切换需二次确认（按钮变"确认开启 LAN？"），不只弹一个"确定/取消"
- 从 `WAN`/`ALL` 回到 `OFF` 不需要确认，但从 `OFF` 到 `WAN` 必须显式说明后果（"外部可访问"）
- 修改配置保存前展示 diff，只列出变更字段
- 不在控制台提供"删除快照""清空索引"这类不可逆操作的一键入口，只提供带确认的单项操作

## 12. 版本与快照

语义定义与存储布局见 `02-数据模型与事务.md`。这里只固定三条对外承诺：

1. **索引版本链**（路径、大小、mtime、哈希、变更类型）对所有来源可信
2. **内容快照**对网关自身写路径（WebDAV 上传、内置页面）可承诺；对 SMB 来源为 best-effort，UI 上必须显示"该版本可能不完整"
3. **移动与重命名永不产生版本**。`versions` 表在移动事务中零写入，这是可被自动化验收的断言

## 13. 安全模型

三层，从外到内，任一层失效仍有兜底。

| 层 | 手段 | 失效后果 |
| --- | --- | --- |
| 一层：开关即边界 | OFF 时零监听、零防火墙规则 | 无 |
| 二层：协议最小化 | 禁 SMBv1、WebDAV 方法白名单、445 只对 localsubnet、WAN 只绑回环 | 攻击面扩大但需先过开关 |
| 三层：目录最小化 | 共享根白名单、VFS 穿越防护、不共享系统盘 | 单目录泄漏 |

额外措施：

- 所有写操作记审计（时间、来源、路径、结果、客户端 IP），滚动文件，默认保留 30 天
- WAN 面可选 IP 白名单与失败登录限速（同 IP 5 次失败锁 10 分钟）
- 进程以 LocalSystem 运行时，防火墙规则命名为 `FSGW-` 前缀，便于人工核查与一键清理
- **控制面单独成域**：`ctlapi` 只绑回环、只接受带 token 的请求、校验 Origin 与 Host（防 DNS rebinding），与 WebDAV 用两套 mux 与中间件。控制面的威胁模型与协议面完全不同——它面对的不是"外部陌生人"而是"用户浏览器里的其它网页"，详见 11.4

## 14. 配置模型

`config.yaml` 放在 `D:\fsgw\config.yaml`（程序目录），与数据分离：

```yaml
version: 1

# 数据目录：SQLite、快照区、日志、state.json
data_dir: D:\fsgw\data

shares:
  - share_id: main
    root: D:\share

    writable: true         # 整个共享可读写（已确认）

  quota_gb: 200

    - { within: 24h, keep: all }
    - { within: 7d,  keep: hourly }
    - { within: 30d, keep: daily }
    - { beyond: 30d, keep: latest }

smb:
  enabled: true
  auth: both               # guest | account | both
  account_name: fsgw
  allow_smb1: false
  bind_profile: private    # 防火墙 profile
  lan_only: true           # 445 只放行 localsubnet

dlna:
  enabled: true
  http_port: 8200
  friendly_name: 家庭共享

  enabled: true
  bind: 127.0.0.1:8443
  tls_cert: ""
  tls_key: ""
  password_hash: ""        # bcrypt
  expose_versions: true
  allow_plain_http_localhost: true

ui:
  enabled: true
  bind: 127.0.0.1:8444     # 只允许回环，配置校验阶段拒绝非回环地址
```

## 15. 可观测性

- `fsgw status`：与 `GET /api/status` 同一份数据，CLI 只是做了格式化
- `GET /healthz`（回环，免 token）：进程存活 + DB 可写。免 token 是为了让外部探针能打，因此**只回 `ok`/`degraded`，不含任何细节**
- `GET /metrics`（回环，需 token，Prometheus 文本格式）：`fsgw_events_total{op}`、`fsgw_write_queue_depth`、`fsgw_reconcile_duration_seconds`、`fsgw_snapshot_bytes`
- 控制台本身即主要观测面：状态、队列深度、审计尾都在 UI 上，不需要另开一套
- 日志：结构化 JSON 行，滚动 20MiB × 5；审计独立文件，不复用调试日志

## 16. 包职责与依赖方向

依赖只能自上而下，`platform` 是最底层，不 import 任何业务包。

```
cmd/fsgw      → app
app           → config, index, vfs, smbhost, dlna, webdav, snapshot, audit, ctlapi, platform
ctlapi        → app(状态机), index(只读统计), config, audit, vfs(路径校验)
webui         → (纯静态资源，只被 ctlapi 通过 embed 引用，不 import 任何 Go 包)
vfs           → index, platform/fileid
webdav        → vfs, index, snapshot(只读)
dlna          → vfs, index
smbhost       → platform/firewall, config
snapshot      → index, platform/link
index         → (无业务依赖)
platform/*    → (仅 x/sys)
```

注意 `webui` 与 `ctlapi` 的边界：前端不知道任何业务规则，所有校验（可写性、路径合法性、状态机前置条件）都在 `ctlapi` 之后的 Go 侧完成。前端只负责展示与收集输入——这样即使前端被改坏，也不会绕过安全校验。
